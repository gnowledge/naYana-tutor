OpenType ligatures (digraphs that render as a single glyph)

Two IPA digraphs are common enough that the font ligates them via a GSUB liga lookup. The underlying text still contains both characters — only the visual rendering combines them.

Diphthongs (Latin-letter compositions, no IPA codepoint)

Nayana spells English diphthongs with two adjacent Latin letters rather than as IPA digraphs (/aɪ/, /eɪ/, /oʊ/, /aʊ/). The visual run-on of the vowel-marker stroke under each letter creates the diphthong feel. In the keyboard, since lowercase a means schwa, diphthongs starting with Latin a use q (which produces a literal Latin a).

Acid test 2 — IPA → audio reachability

Because every non-Latin character above sits at its canonical Unicode IPA codepoint (per the project's IPA-encoding policy), the engine's output is standards-compliant IPA — readable by any tool that consumes IPA. To verify end-to-end that the encoding round-trips through audio synthesis: 

# 1) Install espeak-ng (one of several IPA-aware TTS engines)
sudo apt install espeak-ng

# 2) Run the validator script — extracts IPA from engine output,
#    converts to X-SAMPA (espeak-ng's input format), and prints
#    a ready-to-run espeak-ng command per word.
node engine/scripts/validate-ipa-encoding.js "philosophy is interesting"

# 3) Pipe through espeak-ng to produce a WAV file
node engine/scripts/validate-ipa-encoding.js "philosophy is interesting" --tts /tmp/out.wav

A successful audio file proves: (a) every emitted character is a valid IPA codepoint, (b) the codepoints are correctly identified by external IPA-aware tooling, (c) downstream pipelines (TTS, screen readers, linguistic processing) can consume Nayana output unmodified.
